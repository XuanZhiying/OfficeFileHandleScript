## 1. 目的与适用范围

本文档描述本应用在 Temu 开放平台的**完整功能验证流程**：从应用授权、店铺数据同步，到平台订单转内部订单、发货审核与面单获取的全链路测试步骤、预期结果与判定标准。

适用对象：
- Temu 开放平台应用审核人员（按第 5 章逐步执行即可完成验收）
- 本应用测试 / QA 人员（作为回归测试用例集）

不在本文范围：计费、结算、报表、OMS 对接等与本应用 Temu 能力无关的模块。

## 2. 角色与术语

| 角色 | 说明 |
| --- | --- |
| 分销商（卖家） | 拥有 Temu 店铺、使用本系统的客户，授权后由本系统代其处理订单 |
| 管理员 | 本系统运营管理端账号，可查看分销商授权与同步状态 |
| Temu 卖家中心 | Temu 官方卖家后台，用于确认店铺侧结果 |

| 术语 | 说明 |
| --- | --- |
| 分区（Zone） | 平台按经营形态划分的授权区域。本应用区分 `US`（本土店）与 `PA`（跨境半托管），两个分区使用独立授权凭证 |
| 履约发货仓 | 平台侧可用于发货的仓库（本应用只同步此类仓库，不拉取商品） |
| 等待窗口 | 平台订单拉取后先进入等待池，窗口内不立即转单，用于合并处理（时长沿用店铺配置，默认 30 分钟） |
| 商品匹配来源 | `人工设置` > `平台SKU映射` > `卖家SKU兜底`，人工设置优先级最高且不受后续同步覆盖 |
| 发货审核 | 向平台提交包裹信息（发货仓、包裹重量尺寸、物流渠道）以申请面单的动作 |
| 面单 | 平台物流面单文件（PDF / PNG） |

## 5. 详细测试步骤

### TC-01 应用授权与店铺绑定

**目的**：验证 OAuth 授权链路可用，且授权结果按分区分开保存。

**前置**：D1 已准备；分销商账号有「平台授权」菜单。

**步骤**
1. 用分销商账号登录系统，进入「分销商端 → 平台授权」。
2. 选择平台 `Temu`，点击「授权」。
3. 跳转至 Temu 授权页，使用测试店铺账号登录并确认授权。
4. 等待自动跳回本系统，查看授权列表。

**预期结果**
- 授权列表新增一条记录，状态显示「已授权」，展示店铺名称与店铺 ID。
- 分区标识正确显示（`US` / `PA`），与店铺实际经营形态一致。
- 再次对同一店铺授权时，不产生重复记录，仅更新凭证与授权时间。
- 授权凭证落库为加密存储，页面不回显任何 token / secret。

**判定**：以上预期全部满足为通过。

### TC-02 店铺仓库同步（含分区）

**目的**：验证仓库同步只取履约发货仓、按分区隔离、且重复执行幂等。

**前置**：TC-01 已通过；D2 已准备。

**步骤**
1. 进入「分销商端 → 店铺仓库」，选择已授权店铺。
2. 点击「同步仓库」，在弹窗中确认「将同步分区」显示正确。
3. 打开异步任务中心，等待同步任务完成。
4. 刷新仓库列表，检查仓库条目、分区徽标与默认仓标记。
5. 再次点击「同步仓库」，重复一次。

**预期结果**
- 同步任务在合理时间内完成（一次店铺同步不应拉取平台商品列表，耗时通常在数秒级）。
- 列表仅包含平台履约发货仓，不包含退货仓等不可发货仓库。
- 每条记录的「平台分区」徽标与所选分区一致；不同分区的仓库互不覆盖、互不误标。
- 每个分区至多存在一个「默认仓」；分区不区分仓库默认能力的平台不显示该列。
- 重复同步不产生重复记录，已有仓库的本地配置（默认仓、启用状态）不被冲掉。

**判定**：以上预期全部满足为通过。

### TC-03 平台商品获取

**目的**：验证平台商品数据（含重量与尺寸）能正确取回并换算。

**前置**：D3 已准备。

**步骤**
1. 进入「分销商端 → 平台商品」，选择店铺后点击「同步商品」或「获取商品」。
2. 等待任务完成后查看商品列表。
3. 打开任一带重量尺寸的商品详情，核对重量、长、宽、高。

**预期结果**
- 商品列表包含平台 SKU、图片、标题、售价等基础信息。
- 重量尺寸字段有值：本土店（US 区）按平台 `lb` / `in` 口径展示；跨境店（PA 区）按平台 `mg` / `mm` 换算为本系统单位后展示，换算比例正确。
- 平台侧无重量尺寸的商品，对应字段为空且不报错。
- 手动推送至平台的商品带有「手动推送」标记。

### TC-04 平台订单拉取（含 Webhook）

**目的**：验证订单能通过主动拉取与平台推送两种方式进入系统。

**前置**：TC-01 已通过；D6 已准备。

**步骤**
1. 进入「分销商端 → 平台订单」，点击「拉取订单」（或等待定时任务执行）。
2. 在 Temu 卖家中心对测试店铺新下一笔真实订单，等待平台推送（Webhook），不手动拉取。
3. 查看平台订单列表与订单详情。

**预期结果**
- 主动拉取与平台推送都能新增订单，且同一订单不会重复入库。
- 订单号、商品行、SKU、数量、金额、收件人信息与 Temu 卖家中心一致。
- 新订单先进入等待池（状态为等待处理），等待窗口结束或被手动触发后才进入待转单流程。
- 已停用仓库对应的订单不被处理，且页面有明确提示。
- 订单列表展示「所属仓库」，与平台订单实际履约仓一致。

### TC-05 本平台商品匹配

**目的**：验证「人工设置 > 平台SKU映射 > 卖家SKU兜底」三级匹配规则与持久化。

**前置**：TC-04 已通过；本系统已有可售商品档案。

**步骤**
1. 在平台订单列表中，找到一笔商品行显示「尚未设置」的订单，点击「设置本平台商品」。
2. 在弹窗中选择本系统商品（候选范围应限于该订单所属分销商的已授权品牌）。
3. 选择「暂存」保存，随后重新打开同一订单，确认设置仍然存在。
4. 再次打开弹窗，点击「清除设置」，观察匹配来源变化。
5. 对同一商品额外配置一条「平台SKU映射」，确认优先级低于人工设置。

**预期结果**
- 保存后商品行匹配来源显示「人工设置」，并持久化到数据库（刷新页面、重新同步订单后依然保留）。
- 候选商品列表受品牌授权范围限制，越权品牌商品不可选。
- 人工设置优先于平台SKU映射与卖家SKU兜底。
- 「清除设置」后回落到平台SKU映射或卖家SKU兜底，无匹配时显示「匹配失败」并给出原因。
- 平台未回传卖家 SKU 的订单，可通过人工设置正常完成匹配。

### TC-06 平台订单转内部订单

**目的**：验证平台订单可正确生成内部仓储订单。

**前置**：TC-05 已通过。

**步骤**
1. 在平台订单列表点击「保存并转单」（或对已匹配订单点击「转单」）。
2. 等待任务完成后查看内部订单。
3. 打开生成的内部订单详情，核对商品、数量、收件信息、金额。
4. 返回平台订单列表，再次对同一订单点击转单。

**预期结果**
- 生成内部订单并回写内部订单号，平台订单状态变为「已转单」。
- 内部订单的商品编码、数量、收件人、金额与平台订单一致。
- 重复转单被拦截，给出明确提示，不产生第二张内部订单。
- 存在「匹配失败」商品行时不允许转单，并提示具体失败的订单行。

### TC-07 发货审核与面单获取

**目的**：验证包裹信息提交、物流渠道选择与面单文件获取的完整链路。

**前置**：TC-06 已通过；D4 分区默认包裹参数四项齐全；店铺存在默认仓。

**步骤**
1. 在平台订单列表点击「发货审核」，打开审核弹窗。
2. 确认「发货仓」默认为店铺该分区的默认仓；点击「更改发货仓」可切换为其他已启用履约仓。
3. 点击「获取可用渠道」，等待渠道列表返回。
4. 在物流渠道下拉中选择任一可用渠道（下拉中应展示承运商、服务类型、价格与时效；同一承运商同一服务类型的渠道已合并并标注同款数量）。
5. 点击「提交」，等待异步任务完成。
6. 返回订单列表，点击「查看面单」或「获取面单」，下载面单文件。

**预期结果**
- 弹窗中包裹重量与长宽高为有值状态；美区单位为 `lb` / `in`，跨境区为 `kg` / `cm`。
- 包裹参数取值顺序为：平台商品重量尺寸 → 本系统商品档案重量尺寸 → 分区默认包裹参数，**逐项兜底**（某一项缺失时才用默认值，不整组覆盖）。
- 缺失必需包裹参数时，前端与后端均拦截提交，并提示缺失项。
- 「获取可用渠道」按平台实时报价返回；短时间内重复点击被限流拦截并提示稍后再试。
- 提交成功后：平台订单状态变为已发货，回写运单号与面单地址，面单文件可正常打开。
- 提交失败时：订单被标记为面单获取异常，并展示平台返回的具体原因，可重新发起。
- 「获取可用渠道」为可选动作，不获取渠道也能提交（此时按店铺配置的承运商优先级与最低价自动选渠道）。

### TC-08 面单找回（卖家在 Temu 卖家中心自行出单）

**目的**：验证面单在平台侧已生成、但本系统未参与出单时，仍可把面单取回本系统。

**前置**：D6 预留的订单尚未在本系统做发货审核。

**步骤**
1. 在 Temu 卖家中心，对该订单**自行完成发货并出单**。
2. 回到本系统平台订单列表，点击「刷新」同步订单状态。
3. 对该订单点击「获取面单」。
4. 打开获取到的面单文件，与 Temu 卖家中心的面单比对。

**预期结果**
- 订单在平台侧出单后，系统能识别为「平台已发货、本系统尚无面单」，并展示「获取面单」入口。
- 点击后能取回面单文件并回写运单号、承运商；面单内容与卖家中心一致。
- 该动作只读取平台已有面单，**不会重复向平台申请面单**，不产生额外面单费用。
- 平台尚未出单、卖家自发货、平台不支持该能力时，给出明确的业务提示，不出现系统异常。
- 未完成发货审核或已关闭的订单不展示该入口。

### TC-09 异常与边界处理

**目的**：验证异常路径有明确提示且不产生脏数据。

| 编号 | 场景 | 操作 | 预期 |
| --- | --- | --- | --- |
| TC-09-1 | 授权失效 | 在 Temu 卖家中心解除授权后，在本系统执行同步 | 提示需要重新授权，不抛出系统异常，不写入脏数据 |
| TC-09-2 | 包裹参数缺失 | 清空分区默认包裹参数后做发货审核 | 提交被拦截并提示缺失的重量/尺寸项 |
| TC-09-3 | 地址超区 | 使用平台不可配送的收货地址提交 | 展示平台返回的不可用原因（如地址超区），可更换渠道重试 |
| TC-09-4 | 停用仓库 | 停用正在被订单使用的仓库 | 有二次确认并说明后果；停用后新订单不再按该仓处理，历史数据保留 |
| TC-09-5 | 频繁查询渠道 | 连续快速点击「获取可用渠道」 | 按钮倒计时或被限流拦截，提示稍后再试 |
| TC-09-6 | 重复提交发货审核 | 对同一订单连续提交两次 | 第二次被拦截，不产生两张面单 |

---

### TC-10 解除授权与停用店铺

**步骤**
1. 在分销商平台授权列表，对已授权店铺点击「解除授权」，确认。
2. 回到平台订单列表，确认不再拉取该店铺新订单。
3. 在 Temu 卖家中心新下一笔订单，确认不再通过 Webhook 进入系统。

**预期结果**
- 授权记录状态变为「未授权」，凭证失效。
- 该店铺不再参与订单拉取与 Webhook 处理。
- 历史订单、仓库、商品数据保留，不被删除。

### 附录 B 常见错误码对照

| 错误提示 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `sign is invalid`（3000001） | 参数类型或精度不符合平台要求（数值需按字符串、最短小数形式提交） | 检查请求参数格式后重试 |
| `Wrong package weight information`（120015507） | 美区包裹重量未按整数磅提交，或缺少盎司余量 | 按整数磅 + 盎司余量拆分提交 |
| 包裹重量尺寸缺失 | 分区默认包裹参数未配齐四项 | 补齐默认参数后重试 |
| 无可用物流渠道 | 地址超区、商品类型受限、尺寸超限 | 按页面展示的不可用原因调整后重试 |
| 需要重新授权 | 授权过期或被解除 | 在平台授权页重新授权 |
